# Via

A reusable C/C++ build framework for **host and embedded** development, delivered as a
Nix flake. Applications are configured by a single `Via.toml` (Cargo-style) and built with
CMake/Ninja underneath — usually with **no `CMakeLists.txt`**.

Nix resolves (pins deps, picks the toolchain, computes sources/flags) and CMake builds by
convention from the result. TOML is parsed once, in Nix; the CMake driver is generic and
names no arch flags, chip defines, or MCU "family" layer — the app declares those itself.

## Try the examples

The framework lives at the repo root; runnable demos live under [`examples/`](examples/):

```sh
nix build .#hello          # host application
nix build .#blink          # STM32 firmware (.elf/.bin/.hex)
nix flake check            # build + run host unit tests
nix develop .#hello        # per-app dev shell (cmake/ninja/clangd/gdb)
nix run   .#docs           # build the handbook into docs/book/
```

## Use Via in your own project

Add Via as a flake input and point its engine at your repo — you do not vendor `nix/` or
`cmake/`:

```nix
{
  inputs.via.url = "github:you/via";
  inputs.nixpkgs.follows = "via/nixpkgs";
  inputs.flake-utils.follows = "via/flake-utils";

  outputs = { self, via, nixpkgs, flake-utils }:
    flake-utils.lib.eachDefaultSystem (system:
      let v = via.lib.${system}.mkVia { root = ./.; };
          apps = v.discoverApps ./apps;
      in {
        packages  = v.packagesFor apps;
        checks    = v.checksFor   apps;
        devShells = v.devShellsFor apps;
      });
}
```

See [Consuming Via externally](docs/src/consuming.md) and the full handbook in
[`docs/`](docs/) (`nix run .#docs`, then open `docs/book/index.html`).

## Layout

```
flake.nix           framework outputs: lib.mkVia, packages.docs, example builds
nix/                the engine (via.nix + lib/*) and bundled toolchain records
cmake/              the generic driver: CMakeLists.txt, ViaDriver, ViaToolchain
docs/               the handbook (mdBook source under docs/src)
examples/           a self-contained Via workspace used as the demos:
  Via.toml            workspace manifest (members, shared dep pins)
  Via.lock            resolved git dependency pins
  apps/<name>/        applications: Via.toml + src/ (+ inc/, config/, tests/)
  libs/<name>/        internal libraries (consumed from source)
```

## Concepts

- **Manifest-first.** An app declares package, artifacts (`[[bin]]`/`[[test]]`), platforms,
  dependencies, and language standard in `Via.toml`. CMake is generated by convention; a
  hand-written `<app>/CMakeLists.txt` is an optional escape hatch.
- **The app declares everything device-specific.** Arch flags, chip defines, SDK include
  dirs/sources, startup, and linker script all live on the app's platform — there is **no
  MCU family layer**. Switching chips is just different flags + a different startup/linker.
- **Compiler-only toolchain file.** Selecting GCC vs Clang never touches arch flags;
  libc/spec choices live on the [toolchain record](docs/src/toolchains.md), so the two swap
  untouched.
- **Per-app sealed builds.** Each artifact is its own Nix derivation with its own pinned
  toolchain/SDK/deps, so apps can use different versions side by side.
- **No vendor code generators.** Vendor SDKs are consumed as git dependencies; committed
  assets (linker scripts, startup) live under `<app>/config/`.
- **Bring your own toolchain.** Consumers drop a `toolchains/<id>.nix` at their repo root
  (auto-discovered) or pass it to `mkVia` — see [Toolchains](docs/src/toolchains.md).
